## 二、业内三大典型生产级灾难复盘与避坑防线

### 2.1 事故 1：HTN 分解未设置硬深度截断导致递归循环与 JVM 堆栈溢出
- **事故现象**：某智能客服系统利用大模型递归分解用户复杂多轮退货理赔诉求。在遇到罕见模糊条件时，大模型在“核实物流信息”与“请求用户补充单号”两个复合子任务之间产生循环依赖，系统递归调用自身超过 10,000 次，触发 `StackOverflowError`，工作线程崩溃并导致整个服务实例离线。
- **根本原因**：任务分解仅依赖大模型自然语言提示词控制，底层没有基于 Kahn 拓扑排序的无环约束和强深度势能门禁。
- **Phase 55 防御措施**：在 `HtnTaskDecomposer` 中内置定理 1.1 强深度硬约束 $D_{\max} = 5$，每次分解前进行 Kahn 拓扑排序无环性检测，若发现循环依赖或深度超限，强行终止分解并抛出明确的结构化异常，杜绝堆栈溢出。

### 2.2 事故 2：跨系统智能体执行部分失败未逆向补偿导致数百万资金数据错乱
- **事故现象**：某金融支付自动化 Agent 执行“退款跨行划转”业务，前置动作已成功在第三方渠道扣除保证金，但在向本地结算表写流水时发生数据库唯一索引冲突。由于系统未设计逆向补偿（Compensating Actions），扣款成功而业务单据状态显示失败，造成长达两周的账目不对称和重大对账事故。
- **根本原因**：将分布式多步调用当作单一本地事务对待，缺乏长事务 SAGA 逆向幂等补偿机制。
- **Phase 55 防御措施**：引入 `DistributedTransactionArbiter`，每个正向动作强制注册唯一的幂等逆向补偿算子。当任意下游环节失败且自愈失败时，仲裁器依据依赖图逆序（LIFO）逐一触发逆向补偿动作，确保系统状态 100% 回滚至基准一致态，定理 1.3 消除脏状态残留。

### 2.3 事故 3：盲目暴力重试引发 API 配额熔断与全站级联雪崩
- **事故现象**：某代码自动化 Agent 在调用外部代码构建流水线时遭遇 403 权限拒绝。由于配置了无限循环重试，Agent 瞬间并发重试数百次，不仅耗尽了企业每分钟的 API 调用配额，导致正常线上用户的请求被限流，同时打满连接池引发下游服务雪崩。
- **根本原因**：对非瞬态业务错误（如权限不足、参数格式错误）缺乏因果根因诊断，盲目当作网络瞬态抖动进行暴力重试。
- **Phase 55 防御措施**：引入 `CausalMetaReasoningEngine`，在执行失败时提取错误上下文与因果依赖图，由 DeepSeek-R1 链式推理判定错误是否具备可自愈性（Recoverable）。对非可恢复错误（如权限、缺失不可变前置条件）立刻快速失败并触发 SAGA 补偿；对可自愈错误最多在 3 轮内生成精准元补丁自愈，定理 1.2 保证极速收敛。

## 三、生产级五大核心组件契约设计

在 `backend/qknow-framework/qknow-ai/src/main/java/tech/qiantong/qknow/ai/htn/` 落地五大组件：

1. **`HierarchicalExecutionReceipt.java`**：不可变 Java 21 Record 存证收据，记录 taskId、分解任务树拓扑哈希、原子动作执行轨迹、SAGA 事务状态（COMMITTED / COMPENSATED）、因果自愈轮次与 SHA-256 密码学签名。
2. **`HtnTaskDecomposer.java`**：分层任务网络递归分解器，支持复合任务向原子动作的递归分解、Kahn 拓扑排序无环检测与最大深度硬截断。
3. **`CausalMetaReasoningEngine.java`**：因果元反思自愈引擎，分析执行失败上下文，构建因果诊断图，生成精准元补丁并驱动有限视界反思修正。
4. **`DistributedTransactionArbiter.java`**：分布式 SAGA 事务仲裁器，管理正向动作与逆向幂等补偿序列，保证最终一致性。
5. **`MultiAgentHierarchicalCoordinator.java`**：端到端统筹调度中枢，闭环串联 HTN 分解 -> 拓扑执行 -> 因果元自愈 -> SAGA 事务仲裁 -> 密码学收据签发。

### B01：失败语义的证据边界

冻结 rubric 要求同时出现 `2026-11-31`、`30`、`无效`，禁止 `创建成功`。baseline 第一轮被判 `F`；其保存的 300 字回答前缀已说明“不是有效日期”和“11 月只有 30 天”，但前缀没有精确词 `无效`。完整回答没有存储，只有 `answerSha256`，故**不能独立判定**完整文本究竟缺少 `无效`，还是在截断部分触发了其他字符串条件；也不能把这项归因为日期推理错误。第二轮 baseline 通过，A/B 两轮均通过，没有同题两轮稳定改善。

### B03：工具成功，字符串禁词误伤否定表达

## 候选是否真正生效

- A 的凭单指纹与 baseline 不同，`AlgebraicHarnessMutator` 只把 `corePrinciples` 连续空白折叠为单空格；10 对同题同轮首个 Prompt SHA-256 均与 baseline 不同。**接线生效，但改动是排版压缩，不是新的检索、工具或答案约束。**其 8/10 不能证明提示词压缩有益；B03 两轮的禁词命中也不能单独证明压缩导致语义退化。
- B 的凭单指纹不同，短期窗口由默认 20 缩为 19。Runner 不提供 memory manager；HISTORY 题仅 4 条，其他题 0 条，均低于两个窗口。10 对同题同轮首个 Prompt SHA-256 与 baseline 完全相同。**参数变了，但本题集没有激活窗口裁剪；B 的 9/10 与 baseline 的 8/10 不能归因于算子改善。**同一 B03 首轮/次轮结果翻转也提示模型输出与字符串判据有波动。
- RAG、TOOL、HISTORY、COMPOSITE 的接线不是本批失败瓶颈：12 个 RAG probe 均 `ragUsed>0`；12 个工具任务 probe 均有执行和实际入参；B04 的 source 顺序已在证据中保存。上述计数不构成模型质量或真实业务能力的证明。

## 10/10 与稳定改善门槛

预注册采纳同时要求候选 bootstrap 自身 10/10、无 1→0 退化，以及**同一 task ID 两轮均 baseline 0→候选 1**。A 8/10、B 9/10 已不满足第一条件。更强的结构性限制是：baseline 第一轮失败集合为 `{B01,B03}`，第二轮失败集合为 `∅`，交集为空。因此在**本次已经发生的 baseline 结果**下，任何候选即使达到 10/10，也不可能满足两轮稳定改善；这不能用事后降低到 9/10 来“修复”。10/10 是否普遍过严，单批数据无法证明；但 B03 的子串误伤与未激活的 B 窗口，使当前门槛的判别力不足。首次 `BLOCKED` 的 13 probes 不进入本矩阵或采纳统计。

## 下一步裁决

选择 **B：新任务书中先修任务/rubric 与证据契约**，不是追认本批结果。具体需预注册否定作用域或结构化字段判据，避免把“是否已发凭证/未发凭证”算作肯定已发；在受控范围内保存可独立复算 rubric 的完整脱敏答案或等价判定证据；让 baseline 有可重复失败的任务，并使候选算子实际触发。保留本批原始 rubric、30 个 probe 和负结果不变。

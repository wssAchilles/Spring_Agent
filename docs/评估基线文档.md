# RAG 评估基线文档

> 基于 RAGAS + RAGChecker 双框架的自动化评估流程
> 最后更新：2026-07-04

---

## 1. 概述

本项目使用两套评估框架对 RAG 管线质量进行量化监控：

| 框架 | 评估粒度 | 核心指标 | 用途 |
|------|----------|----------|------|
| **RAGAS** | Component-level | faithfulness, answer_relevance, context_precision, context_recall, factual_correctness | 组件级质量诊断 |
| **RAGChecker** | Claim-level | precision, recall, F1, hallucination | 声明级事实核查 |

两套框架互补：RAGAS 诊断"哪个组件有问题"，RAGChecker 诊断"哪句话有问题"。

## 3. 黄金数据集

### 数据来源

- **存储位置**：PostgreSQL `eval_dataset_item` 表（dataset_id=1）
- **数据格式**：每条包含 query、expected_answer、ground_truth_contexts（JSON 数组）
- **当前规模**：10 条，覆盖 Day01-Day17-18 的实习日志

### 数据集要求

| 字段 | 要求 | 说明 |
|------|------|------|
| query | 中文自然语言问题 | 模拟真实用户查询 |
| expected_answer | 简短期望答案描述 | 用于人工参考，不参与自动评分 |
| ground_truth_contexts | JSON 数组，包含实际文档内容 | 作为 RAG 检索的理想结果 |

### 注意事项

- ground_truth_contexts 必须是实际文档内容，不是关键词标签
- query 必须与 contexts 内容匹配（不能问"性能优化"但存"昵称功能"的内容）
- contexts 应覆盖回答该 query 所需的完整信息

## 4. 运行评估

### 4.1 RAGAS 评估

```bash
cd backend
mvn test -pl tests -Dtest="RagasFullEvaluationTest#loadFromDbAndEvaluate" -DfailIfNoTests=false
```

**输出示例**：
```
=== RAGAS Summary ===
faithfulness:        0.990
answer_relevance:    0.990
context_precision:   0.945
context_recall:      0.990
factual_correctness: 0.990
```

### 4.2 RAGChecker 评估

```bash
cd backend
mvn test -pl tests -Dtest="RAGCheckerFullEvaluationTest#loadFromDbAndEvaluate" -DfailIfNoTests=false
```

**输出示例**：
```
=== RAGChecker Summary ===
avg_precision:    0.983
avg_recall:       0.950
avg_f1:           0.958
avg_hallucination:0.017
```

### 4.3 评估耗时

| 框架 | 10 条数据 | 平均每条 |
|------|-----------|----------|
| RAGAS | ~55 秒 | ~5.5 秒 |
| RAGChecker | ~52 秒 | ~5.2 秒 |

每条数据的 LLM 调用次数：
- RAGAS：8 次（1 次生成 + 7 次指标评分）
- RAGChecker：N+1 次（1 次 claim 提取 + N 次蕴含判断）

## 5. 评估流程架构

```
┌─────────────────────────────────────────────────────────┐
│                    黄金数据集                             │
│         eval_dataset_item (dataset_id=1)                │
│  query + expected_answer + ground_truth_contexts        │
└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│                 LLM 生成答案                             │
│    ChatModelFactory → DeepSeek → generated_answer       │
└─────────────────────┬───────────────────────────────────┘
                      │
              ┌───────┴───────┐
              ▼               ▼
┌──────────────────┐  ┌──────────────────┐
│    RAGAS 评估     │  │  RAGChecker 评估  │
│                  │  │                  │
│ 7 项并行指标评分  │  │ claim 提取       │
│ (30s 超时/指标)   │  │ → 蕴含判断       │
│                  │  │ → 指标计算       │
│ faithfulness     │  │                  │
│ answer_relevance │  │ precision        │
│ context_precision│  │ recall           │
│ context_recall   │  │ F1               │
│ factual_correct  │  │ hallucination    │
└────────┬─────────┘  └────────┬─────────┘
         │                     │
         ▼                     ▼
┌─────────────────────────────────────────────────────────┐
│                 评估报告                                 │
│  - 每条数据的逐项分数                                    │
│  - 汇总统计（mean/P50/P90）                              │
│  - 与基线对比                                            │
└─────────────────────────────────────────────────────────┘
```

## 7. 回归检测

### 判定规则

| 场景 | 判定 | 处理 |
|------|------|------|
| 所有指标 ≥ 阈值 | ✅ PASS | 正常发布 |
| 任一指标 < 阈值 | ❌ FAIL | 阻断发布，排查原因 |
| 指标下降 > 5% | ⚠️ WARNING | 人工审查 |

### 排查流程

1. 查看每条数据的逐项分数，定位低分条目
2. 检查低分条目的生成答案和 contexts
3. 分析是检索问题（contexts 不相关）还是生成问题（答案不忠实）
4. 检索问题 → 排查 Rerank/召回逻辑；生成问题 → 排查 Prompt/模型

## 8. 扩展数据集

### 添加新评估条目

```sql
INSERT INTO eval_dataset_item (dataset_id, query, expected_answer, ground_truth_contexts)
VALUES (
    1,
    '新问题',
    '期望答案描述',
    '["实际文档内容1", "实际文档内容2"]'
);
```

### 从知识库提取 contexts

```sql
-- 随机抽取某文档的 chunk 作为 ground_truth_contexts
SELECT jsonb_agg(content)
FROM (
    SELECT content
    FROM vector_store
    WHERE metadata->>'kmc_document_name' = '目标文档名'
      AND content NOT LIKE '%title page%'
      AND content NOT LIKE '%目录%'
    LIMIT 2
) t;
```
